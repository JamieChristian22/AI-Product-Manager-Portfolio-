# AI Product Manager — Source-Backed Validation & Interactive Demo

## Scope and reproducibility

**[Open the offline interactive AI Product Evidence Explorer](../demo/ai-product-evidence.html)**. Download the HTML and open it in a browser (with repository directories preserved for source-file links). No services, customer data, model endpoints, tokens, or external JavaScript are involved.

This portfolio contains four simulated product case studies:

1. [AI E-commerce Revenue Optimizer](../AI_Ecommerce_Revenue_Optimizer/)
2. [AI Product Operational Intelligence](../AI_Product_Operational_Intelligence/)
3. [AI Smart Personalization Platform](../AI_Smart_Personalization_Platform/)
4. [AI User Funnel Conversion Engine](../AI_User_Funnel_Conversion_Engine/)

**Important limitations**: All four case studies reuse the exact same **five-row** synthetic `Data_Analytics/dataset.csv` fixture. The first two projects also reuse the exact same **18-row** AI model-evaluation CSV. Counts must not be added together as separate training datasets, model experiments or independent validation observations. For example, 3/5 sample conversions = 60% **in that authored fixture**, and the 460.49 sample revenue is not a real measured product improvement or a test of the README's separate modeled impact claims.

## Offline validation command

Run from the root with Python 3.11+ and **no third-party packages**:

```bash
python -m tools.validate_ai_products --output reports/source-evidence.json
python -m unittest discover -s tests -p "test_*.py" -v
```

`tools/validate_ai_products.py` verifies:

- Four CSV analytics datasets with unique IDs, binary conversion/retention, nonnegative cent-precision revenue and valid numeric fields.
- **16 actual SQLite comparison checks:** four independently executed committed `queries.sql` statements in each of four projects, compared with standard-library Python KPI calculations.
- Eighteen modeled metric gate comparisons in **each** of the first two projects (including strict `>`, `>=`, `<`, `<=`, and zero policy-violation cases). `status=Pass` is checked against the stored modeled number and threshold; this **does not rerun model training, evaluation, or online inference**.
- Existing monitoring-threshold tables in the personalization and funnel projects (unique metrics, ordered warning/critical boundaries, contextual status in the *recorded* synthetic table).
- Risk register likelihood × impact scores in the personalization and funnel projects.
- The funnel project's 12 authored acceptance records and its status disclosure. Their CSV `PASS` entries **are not executable test results**; CI marks product acceptance execution **UNVERIFIED**.
- Machine-readable `reports/source-evidence.json` for every CI run with shared-fixture disclosure.

`tests/test_ai_product_evidence.py` includes deliberate invalid input and boundary cases. `tests/test_evidence_dashboard.py` verifies every interactive dashboard record exactly matches its canonical source CSV and checks for safe DOM rendering and accessible input labels. No report generated by this workflow proves causal product lift, regulatory compliance, fairness, production uptime, real security/privacy protection or live rollout approval.

## CI and security

[GitHub Actions](../.github/workflows/validate-ai-pm.yml) runs Python 3.11 and 3.12 source reconciliation and regression tests plus a full reachable Git-history Gitleaks scan with a verified binary. This workflow does not install `pandas`, so the older `Data_Analytics/analysis.py` scripts that import `pandas` are **not** included as executable CI gates. Their simple KPIs are instead recomputed using standard-library Python **and independently verified with the committed SQL**. Adding pinned optional pandas dependencies and a verified CLI wrapper is future work.

Before citing a green status, check the **latest** feature-branch GitHub Actions run. No system deployment or external data collection was performed.
